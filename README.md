# DSH 提示词优化助手

> 一键优化输入框提示词，支持本地规则零成本优化 + 角色化 LLM 深度语义优化双模式

![dsh-version](https://img.shields.io/badge/DSH-v0.2.0--rc.2-blue)
![license](https://img.shields.io/badge/license-MIT-green)
![version](https://img.shields.io/badge/version-0.3.0-orange)

## ✨ 功能特性

- 🚀 **双引擎优化**：本地规则零成本毫秒级优化 + LLM 大模型深度语义优化
- 🔍 **信息抽取式重构**：本地引擎会抽出平台、业务指标、数据表、技术栈与约束，再按场景紧凑重组，不是给原文贴一层角色标签
- 🧭 **场景路由**：自动识别数据对账 / 代码开发 / 文档写作 / 问答，只套最匹配的一个模板
- 🚫 **零占位符**：输出里不会出现 `[待补充]`、`TODO`、`xxx` 这类标记；缺失信息要么不写，要么写「按常规处理」
- 📏 **篇幅克制**：优化后不超过原文 3 倍，短诉求短输出，不套五段式模板
- 🎭 **角色可选**：内置 6 个专业角色，默认**不注入**；手选后只加 1 行能改变回答行为的提示（如「先给结论再给依据」），支持完全自定义
- 🔄 **自动降级**：LLM 调用失败或输出含占位符时自动切换本地规则，保证功能可用
- 🎨 **原生整合**：深度适配 DSH 桌面端 v0.2.0-rc.2，按钮与设置页原生注入，自动适配深色/浅色主题
- ↩️ **一键撤销**：优化后可快速恢复原始文本，操作无风险

## 🚀 快速安装

### 方式一：在线安装（推荐）

```bash
dsh plugin add https://github.com/nanji0710/DSH-prompt-optimizer
```

### 方式二：手动安装

1. 前往 [Releases](https://github.com/nanji0710/DSH-prompt-optimizer/releases) 下载最新版本 `prompt-optimizer-v0.1.0.zip`
2. 解压到本地目录
3. 在 DSH 中执行：

```bash
dsh plugin add ./解压后的目录路径
```

## 📖 使用方法

1. 在 DSH 输入框中输入原始提示词
2. 点击输入框工具栏模型选择器左侧的「✨ 优化提示词」按钮，一键完成优化
3. 优化后点击「↩ 撤销」可恢复原始文本
4. 打开 `设置 → 提示词优化助手`，可切换优化模式、选择专业角色、调整本地规则、管理自定义角色

## ⚙️ 配置说明

### 基础设置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| 优化模式 | 大模型深度改写 | 大模型深度改写（推荐）/ 本地规则（不调用模型，零成本） |
| 接口 / Provider | 空（用 DSH 默认） | LLM 模式下使用的接口，留空时使用 DSH 当前默认模型 |
| 模型名称 | 空（用 DSH 默认） | LLM 模式下使用的模型名称 |
| 采样温度 | 0.2 | 0-1，值越低优化结果越稳定。改写任务建议 0.1-0.3 |

> 💡 LLM 深度优化直接复用 DSH 中已配置的模型服务，**无需额外接入 API、无需单独配置密钥**。调用失败时自动降级为本地规则。

### 角色专项优化

角色**默认不注入**——「你是资深 XX 工程师」这类人设对回答质量没有增量，只会占篇幅。只有选中非「通用角色」并开启「注入角色行」后，才会在开头加 1 行：

| 内置角色 | 注入的那一行 |
|----------|--------------|
| 前端开发工程师 | 你是一名前端工程师，回答时先给可运行的代码再解释关键逻辑。 |
| 后端开发工程师 | 你是一名后端工程师，回答时先给接口与数据结构设计再给实现。 |
| 产品经理 | 你是一名产品经理，回答时先给用户场景与验收标准再展开方案。 |
| 数据分析师 | 你是一名数据分析师，回答时先给结论再给依据。 |
| 文案策划 | 你是一名文案策划，回答时先给成稿再给可替换的备选表达。 |
| 通用角色 | （空，等于不注入） |

支持添加任意自定义角色，提示词只需写**一句能改变回答行为的**话（顺序 / 粒度 / 风格）。

### 本地优化规则

本地引擎分两步：**信息抽取 → 紧凑重组**。抽不出来时退回兜底模板，只做客套清理。

- **信息抽取**：平台/公司、业务指标、数据表、技术栈、时间范围、范围限定、输出要求
- **动作导向**：改写成「请 + 动词」开头的指令
- **紧凑重组**：按场景（数据对账 / 代码开发 / 文档写作 / 问答）套用最匹配的一个模板；数据对账类会要求「定位环节 + 验证方法 + 修正建议」三要素
- **注入角色行**：默认关闭；开启后只加 1 行
- 已足够清晰的原文（带小节标记、或自己写明了时间/范围/输出格式）**原样透传**，不强行加结构

## 🛠️ 本地开发

### 环境要求

- Node.js ≥ 18
- DSH 桌面端 v0.2.0-rc.2

### 构建

```bash
npm install
npm run build
```

构建产物输出至 `dist/`：

- `dist/index.js`：插件服务端（tsc 编译）
- `dist/config.js`：配置 Schema 与默认值
- `dist/local-optimizer.js`：本地规则引擎
- `dist/client/index.js`：客户端打包产物（esbuild 单文件）

### 目录结构

```
src/
├── index.ts               # 插件主入口，服务注册
├── config.ts              # 配置 Schema、默认值、内置角色
├── local-optimizer.ts     # 本地正则规则引擎
├── types/external.d.ts    # DSH 宿主模块类型声明
└── client/
    ├── index.tsx          # 客户端入口，插槽注入
    ├── OptimizeButton.tsx # 优化按钮组件
    └── SettingsPage.tsx   # 设置页面组件
```

> 说明：`@deepseek-ai/dsh-*`、`cordis`、`react` 由 DSH 宿主运行时提供，本地构建通过 `.npmrc` 的 `legacy-peer-deps=true` 跳过安装，打包时标记为 external。

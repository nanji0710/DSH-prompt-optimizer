## 一、它解决什么问题

用 AI 干活时，最大的浪费不是 AI 不够聪明，而是**需求没说清楚**。

| 常见的写法 | 结果 |
| --- | --- |
| 「帮我看看这个数据对不对」 | AI 不知道看哪张表、对什么、按什么口径 |
| 「写个爬虫」 | AI 反问你爬什么网站、用什么语言，来回好几轮 |
| 「总结一下」 | 输出一大段没有重点的复述 |

这个插件的作用，就是在你**点下发送之前**，把你随手写的一句话补全成一份结构完整、可直接执行的需求：**明确目标、明确对象、明确交付标准**，同时不改变你原本的意思。

**最大的好处**：不用再学「提示词技巧」，按平时的说话习惯打字，点一下 ✨ 就行。

## 二、三步上手

### 1. 装上

在 DSH 里执行（任选一种）：

```bash
# 方式一：直接从 GitHub 安装（推荐）
dsh plugin add https://github.com/nanji0710/DSH-prompt-optimizer
```

```bash
# 方式二：从 Releases 下载 .tgz 附件，再把文件名替换成你实际下载的那个
dsh plugin add ./prompt-optimizer-0.3.5.tgz
```

> 下载地址：[Releases](https://github.com/nanji0710/DSH-prompt-optimizer/releases)

安装后**重启一次 DSH**。

### 2. 用起来

1. 在输入框里按平时的习惯写一句话，**不用刻意组织语言**
2. 点输入框底部工具栏右侧的 **✨** 按钮（在模型名称「DeepSeek-V4.1-Flash」的左边）
3. 输入框里的文字会被替换成优化后的版本，直接回车发送

> 点错了？按旁边的 **↩** 按钮一键还原，**没有任何风险**。

### 3. （可选）调设置

`设置 → ✨ 提示词优化助手`，可以切换优化模式、指定用哪个模型、管理角色。

**默认配置就是推荐配置，不改也能直接用。**

## 三、效果对比

### 例 1：数据对账（业务同学最常用）

**你写的（27 字）**

```
拼多多的GMV和去退数量，结果表和底表有差异，你查一下
```

**点一下 ✨ 之后（93 字）**

```
请排查拼多多（GMV、去退数量）在结果表与底表间差异：
1. 定位出在取数口径、计算逻辑、关联聚合还是调度时效
2. 给一条可验证的 SQL 或检查方法
3. 给修正建议，不要改线上数据
```

变化点：**平台和指标被明确点名**，并且告诉 AI「要沿着哪四条路去查」以及「结论要给出可验证的方法」——这正是数据分析类问题的关键。

### 例 2：写东西

| 你写的 | 优化后 |
| --- | --- |
| `帮我写个请假条` | `写个请假条：按常规补齐缺失信息，不要反问。` |
| `总结下这份周报` | `总结下这份周报：Markdown 格式，结论先行。` |
| `做个用户增长的方案` | `做个用户增长的方案：Markdown 格式，结论先行。` |

### 例 3：代码类

| 你写的 | 优化后 |
| --- | --- |
| `写个爬虫` | `写个爬虫：给可直接运行的完整代码，标注语言。` |
| `把这段代码重构一下` | `把这段代码重构一下：给可直接运行的完整代码，标注语言。` |

> 以上均为**本地规则**引擎的实际输出（可逐字复现）。大模型模式会在此基础上进一步补全业务背景与细节，篇幅略长，但写法风格一致。

## 四、它是怎么做到的

插件里有两个引擎，**默认用第一个**：

### 🧠 大模型深度改写（推荐）

调用 **DSH 里已经配好的模型**来改写你的需求。

- ✅ **不需要额外申请 API、不需要单独填密钥** —— 直接用你现在聊天用的那个模型
- ✅ 会先「读懂」你的意图（是在问问题？还是在派活？），再按对应方式补全
- ✅ 会保留你原文里的关键信息：数字、术语、变量、代码，一个都不会被改掉
- ✅ 如果模型服务临时不可用，**自动切到本地规则**，按钮永远不会点了没反应

### ⚡ 本地规则（零成本）

不调用任何模型，纯本地毫秒级完成（实测约 0.1 毫秒）。

- 自动抽取你话里的**关键信息**：平台、业务指标、数据表、技术栈、时间范围、限制条件
- 判断你是在**对账 / 开发 / 写文档 / 提问**，套用最匹配的一种表达方式
- 已经写得很清楚的原文**原样放行**，不会强行加一堆没用的结构

> 两种模式的输出**风格完全一致**，可以随时切换对比。

## 五、设置项说明

### 优化模式

| 选项 | 说明 |
| --- | --- |
| 大模型深度改写（推荐） | 效果最好。调用 DSH 已接入的模型 |
| 本地规则 | 不调用模型、零成本、离线可用。适合批量快速处理 |

### AI 接口（仅大模型模式）

全部用下拉选择，**不需要手打**：

| 设置项 | 默认 | 说明 |
| --- | --- | --- |
| 接口 / Provider | 跟随 DSH 默认 | 你装了哪些接口，这里就列哪些 |
| 模型 | 跟随 DSH 默认 | 选定接口后，自动列出该接口支持的模型 |
| 思考强度 | 自动（推荐） | 档位由模型自己声明。选「自动」会用模型默认档，**不会出现"该模型不支持此强度"的报错** |
| 采样温度 | 0.2 | 0-1。越低越忠实原文，越高越灵活。改写任务建议 0.1-0.3 |

> 💡 拿不准就全部保持「跟随 DSH 默认」。

### 优化角色（默认关）

内置 6 个角色，**默认不注入**——因为「你是资深 XX 工程师」这类身份描述对回答质量没有实际提升，只会白占篇幅。

如果你希望 AI 换一种回答**顺序或风格**，可以再开启：

| 角色 | 开启后额外加的那一句话 |
| --- | --- |
| 数据分析师 | 你是一名数据分析师，回答时先给结论再给依据。 |
| 前端开发工程师 | 你是一名前端工程师，回答时先给可运行的代码再解释关键逻辑。 |
| 后端开发工程师 | 你是一名后端工程师，回答时先给接口与数据结构设计再给实现。 |
| 产品经理 | 你是一名产品经理，回答时先给用户场景与验收标准再展开方案。 |
| 文案策划 | 你是一名文案策划，回答时先给成稿再给可替换的备选表达。 |
| 通用角色 | （等于不注入） |

点 **＋ 添加自定义角色** 可以自己加，**只需写一句能改变回答行为的话**（比如「先给结论再给依据」「多用表格呈现」）。

## 六、常见问题

**Q：优化了但我不满意怎么办？**
A：点 **↩** 一键还原，或者直接手动改几个字。原文永远不会丢。

**Q：会不会改变我的原意？**
A：不会。插件只做「补全」和「重组织」，你原文里写明的对象、数量、范围、禁止事项都会被原样保留。

**Q：输出里会不会出现「[待补充]」这种要我填的空？**
A：不会。插件明确禁止输出任何占位符——信息不足时要么不问，要么写成「按常规处理」。这是这个插件的硬性设计。

**Q：会不会把我的话越改越长？**
A：不会。有硬性篇幅上限——一句话的诉求，改完通常还是一两句话（短诉求最多补到 300 字以内）。不会出现「原话一句、输出一篇」的情况。

**Q：点 ✨ 没反应？**
A：先确认输入框里不是空的。如果显示「LLM 失败，已降级为本地规则」，说明模型服务临时不可用，优化仍然完成了。

**Q：能离线用吗？**
A：可以。把优化模式切到「本地规则」即可，完全不联网。

<summary>展开：本地开发、构建与架构说明</summary>

### 环境要求

- Node.js ≥ 18
- DSH 桌面端 v0.2.0-rc.2

### 构建与测试

```bash
npm install
npm run build       # tsc 编译服务端 + esbuild 打包客户端
npm run typecheck
npm test            # 本地引擎 109 项断言
node scripts/smoke-test.cjs   # 端到端 30 项断言（CI 使用的就是它）
```

构建产物：

- `dist/index.js` —— 插件服务端（`tsc` 编译）
- `dist/config.js` —— 配置 Schema 与内置角色
- `dist/local-optimizer.js` —— 本地规则引擎
- `dist/prompt.js` —— LLM 侧 system prompt 与占位符检测
- `dist/client/index.js` —— 客户端单文件打包（esbuild）

### 目录结构

```
src/
├── index.ts               # 插件主入口：服务注册、三个 HTTP 端点、LLM 改写与降级
├── config.ts              # 配置 Schema、默认值、内置角色
├── prompt.ts              # LLM 侧 system prompt、占位符检测、语言识别
├── protocol.ts            # 前后端共享的请求/响应类型
├── local-optimizer.ts     # 本地规则引擎（信息抽取 → 紧凑重组）
└── client/
    ├── index.tsx          # 客户端入口：插槽注入
    ├── bridge.ts          # 与宿主通信的传输层
    ├── OptimizeButton.tsx # 输入框 ✨ 按钮
    ├── SettingsPage.tsx   # 设置页
    ├── store.ts           # 配置读写
    └── optimize.ts        # 本地引擎的客户端调用封装
```

### 与宿主的通信

客户端通过 `connection.rpc` / 原生 `fetch` 调用插件注册的三个端点：

| 端点 | 用途 |
| --- | --- |
| `POST /api/prompt-optimizer/optimize` | 改写提示词（LLM 失败时响应体里带 `fallback`，由本地引擎产出） |
| `POST /api/prompt-optimizer/providers` | 读取宿主已注册的接口列表（驱动设置页下拉） |
| `POST /api/prompt-optimizer/models` | 读取指定接口的模型与思考强度档位（驱动设置页下拉） |

### 已知限制

- 用 `link:`（Junction）方式安装时，DSH 的客户端 HMR 不会追踪本插件的产物。**改动 `dist/client/index.js` 后需要完整重启 DSH**，刷新页面不够。
- 宿主侧代码（`dist/index.js`）的改动同样需要重启 DSH。
